# ADR 001 — Start with OpenCode and offline Linux isolation

Status: proposed implementation; pilot selection OpenCode confirmed (2026-11-04).

## Context
Hosts use macOS and Linux; OpenCode/Codex/Claude Code are local CLI tools. The user wants to reduce exposure of physical device and residential IP, eventually using an Ubuntu Server Raspberry Pi 3B for network egress control. Different OpenCode versions have distinct permission schemas.

## Decision
First target: OpenCode, then Codex, then Claude Code. Begin with an offline Linux-only bubblewrap proof of isolation. Do not silently execute on host when safeguards are unavailable. Only after adversarial testing add credentials and external network egress. Treat Raspberry Pi gateway as a separately evaluated component, not a prerequisite for offline tests.

## Trade-offs
- Offline OpenCode cannot contact hosted models; this phase validates isolation, not productive AI usage.
- Linux bubblewrap is testable without privileged daemon, but relies on user namespaces and cannot run native macOS applications.
- macOS requires a distinct backend, likely a constrained Linux VM for portable CLIs.
- Isolation cannot prevent identification by account credentials, source code, prompts or application-level telemetry.
